# Povod UI Rules

## Главное правило

Интерфейс должен ощущаться как красивый конструктор праздничной карточки, а не как админка.

## Approved SVG Logo

- Source: `docs/design/assets/logo-reference/gift_arch_symbol_exact_v2.svg`
- UI copy: `public/brand/povod-logo.svg`

Правила:

- не перерисовывать;
- не менять форму;
- не заменять random icon;
- не использовать старый логотип;
- масштабировать аккуратно, сохраняя пропорции.

## Layout

- Сначала главный сценарий, потом вторичные функции.
- Использовать card-first структуру.
- Не делать набор одинаковых белых блоков.
- Визуальная история “хаос -> одна ссылка -> праздник” должна быть понятна на ключевых экранах.

## Header

- Использовать approved SVG logo.
- Header мягкий, теплый, воздушный.
- Desktop высота: 64-72px.
- Mobile компактный.
- Не перекрывать контент.
- Авторизованное состояние: `Мои поводы`, `Выйти`.

## Hero

- Hero объясняет продукт за 3 секунды.
- Главный герой: preview карточки праздника или история “чат -> ссылка -> карточка”.
- CTA: `Создать карточку праздника`.
- Не делать hero тяжелым SaaS-блоком.

## Карточки

- Большие скругления.
- Теплый surface.
- Тонкая теплая рамка.
- Легкая тень.
- Понятная иерархия: title, detail, status/action.

## Кнопки

Primary:

- коралловый фон;
- белый текст;
- мягкий hover;
- понятный глагол.

Secondary:

- светлая поверхность;
- тонкая рамка;
- шоколадный текст.

Disabled:

- читаемый;
- спокойный;
- без исчезновения.

## Формы и поля ввода

- Labels обязательны.
- Placeholder только как пример.
- Поля теплые, с мягкими рамками.
- Ошибки рядом с полем.
- Не оставлять дефолтный технический вид.

## Upload Photo

- Не оставлять стандартный file input.
- Использовать визуальный блок: зона фото, иконка, подсказка, состояние загрузки.
- Фото праздника должно усиливать карточку.

## Stepper

- Stepper дружелюбный и понятный.
- Показывает прогресс создания карточки.
- Не выглядит как скучная техническая навигация.

## Gift Cards

- Показывать фото, название, цену, ссылку и статус брони подарка.
- Статусы: свободен / подарок забронирован.
- Всегда уточнять “бронь подарков”, если возможна путаница.

## Public Event Card

- Должна ощущаться как приглашение для гостя.
- Не делать обычным technical preview.
- Главные детали: дата, время, место, карта, пожелания, подарки.

## Share Panel

- Главный объект: одна ссылка.
- Основное действие: скопировать / отправить.
- Визуально показывать, что ссылка заменяет хаос сообщений.

## Empty States

- Мягкий текст.
- Следующий шаг.
- Теплая карточка, не пустой белый блок.

## Mobile-first

- Проверять 390px.
- Не допускать горизонтальный скролл.
- CTA виден и нажимаем.
- Header не перекрывает контент.
- Карточки идут одной колонкой, если текст ломается.

## Hover / Focus / Disabled

- Hover: небольшой подъем, легкая тень.
- Focus: заметный и доступный.
- Disabled: читаемый и спокойный.

## Отступы

- Ритм 8 / 12 / 16 / 24 / 32.
- Без больших пустых провалов.
- Не прижимать текст к рамкам.

## Скругления

- Основные карточки: `--radius-xl` / `--radius-lg`.
- Малые элементы: `--radius-md` / `--radius-sm`.
- Chips / pills: `--radius-pill`.

## Иконки

- Дружелюбные, line или soft-filled.
- Не использовать случайные наборы.
- Иконки поддерживают сценарий, а не служат декором ради декора.
