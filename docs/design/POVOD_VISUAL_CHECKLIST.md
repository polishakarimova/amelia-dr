# Povod Visual Checklist

Перед завершением любой дизайн-задачи проверь:

## 1. Проект

- Это точно проект «Повод»?
- Нет ли в тексте, файлах, ветках или компонентах названий другого проекта?
- Не перенесены ли случайно брендовые решения из «Собрались»?

## 2. Сценарий

- Пользователь понимает, где он находится?
- Понятно ли главное действие?
- Нет ли лишних блоков на первом экране?
- Визуальная красота помогает сценарию или отвлекает?

## 3. Визуальная чистота

- Достаточно ли воздуха?
- Не слишком ли много текста?
- Не слишком ли много конкурирующих акцентов?
- Не слишком ли жирные шрифты?
- Есть ли ясная иерархия?

## 4. Компоненты

- Кнопки выглядят как часть одной системы?
- Карточки не вложены друг в друга?
- Статусы читаются?
- Иконки в одном стиле?
- Повторяющиеся элементы имеют одинаковый ритм?

## 5. Цвета

- Есть ли нормальный контраст?
- Акцент не слишком яркий?
- Нет кислотных цветов?
- Палитра не выглядит случайной?
- Интерфейс не построен на одном оттенке без системы?

## 6. Типографика

- Заголовки читаются?
- UI-текст не слишком мелкий?
- Длина строк комфортная?
- Текст внутри кнопок и чипов не ломается?

## 7. Mobile

- Ничего не вылезает за экран?
- Кнопки нажимаются удобно?
- Карточки не слишком узкие?
- Чипы читаются?
- Заголовки не перекрывают соседние элементы?

## 8. Техническая проверка

- Изменения ограничены задачей?
- Страницы, API, бизнес-логика и база данных не изменены, если задача была только про дизайн-документацию?
- Запущены доступные проверки из `package.json`, если были изменения в коде?
- В финальном отчёте перечислены изменённые файлы?
